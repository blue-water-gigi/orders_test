# Обработка заказов

## 1. Инструкция по запуску

Нужен PHP 8.1 или выше. Скрипт использует только встроенные возможности PHP.

### Локальный запуск

Запустить встроенный пример:

```bash
php orders.php
```

Передать JSON-файл:

```bash
php orders.php orders.json
```

Прочитать JSON из стандартного ввода:

```bash
php orders.php - < orders.json
```

Посмотреть справку:

```bash
php orders.php --help
```

### Запуск в Docker

Собрать образ из каталога проекта:

```bash
docker build -t orders-processor .
```

Запустить встроенный пример:

```bash
docker run --rm orders-processor
```

Передать JSON-файл из текущего каталога контейнеру через stdin:

```bash
docker run --rm -i orders-processor php orders.php - < orders.json
```

Можно передать путь к JSON-файлу, доступному внутри контейнера:

```bash
docker run --rm -v "$PWD:/data:ro" orders-processor php orders.php /data/orders.json
```

Скрипт возвращает код `0` при успешной обработке, `1` при ошибке документа или ввода, `2` если отдельные записи были пропущены из-за ошибок.

## 2. Пример результата

Для встроенного исходного набора данных вывод будет таким:

```text
Оплаченных заказов: 3
Сумма оплаченных заказов: 4500
Самый дорогой оплаченный заказ: № 103 на сумму 3000
Заказы по статусам:
  paid: 3
  pending: 1
```

## 3. Принятые решения при обработке ошибок

- JSON разбирается с `JSON_THROW_ON_ERROR`. Если документ повреждён, скрипт пишет причину в stderr, не формирует сводку и завершает работу с кодом `1`.
- Корневое значение должно быть JSON-массивом. Объект, строка, число или `null` вместо массива считаются ошибкой всего входного документа.
- Для заказа обязательны `id` (целое число), `customer` (непустая строка), `amount` (целое или дробное конечное число не меньше нуля) и `status` (`paid` или `pending`). Строки, похожие на числа, не преобразуются автоматически.
- Некорректная запись описывается в stderr с её порядковым номером и пропускается. Обработка остальных записей продолжается; сводка строится только по валидным заказам.
- Если были пропуски, итоговый частичный результат остаётся в stdout, а программа возвращает код `2`, чтобы вызывающая сторона могла заметить проблемы данных.
- Сумма `0` считается корректной: заказ включается в число заказов своего статуса.
- Если оплаченных заказов нет, выводятся нулевое количество и сумма, а вместо максимального заказа — сообщение об его отсутствии.
